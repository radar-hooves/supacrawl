What does supacrawl promise someone who installs it from PyPI?

The README and product brief say one install gives a command line, a Python library, a Firecrawl-style web API and an MCP server. From PyPI the MCP server cannot start, because it is built on a private library. It is also the part your own sessions use most (over ten thousand calls in a month). Suggested wording: "a CLI, a Python library and a Firecrawl-shaped REST API from one pip install; the MCP server runs from the maintainer's container image". Your sentence is all that waits; about five documents then follow, no code. Detail: docs/research/holistic-review-decisions.md.

Should the "agent" command, which lets a local model browse on its own, be deleted?

It is about 830 lines, has no tests, nobody has asked for it since the first release, and every household caller is already an agent. Suggested: cut it, with one changelog line. The risk is a stranger among the monthly PyPI downloads who uses it and would find it gone. Detail: docs/research/holistic-review-decisions.md.

Do you still want the settings dashboard that the config schema endpoint was built for?

Five months on, nothing in the estate calls that endpoint. If the dashboard is dead, the endpoint and its display metadata go when the settings are folded into one system; the config command and its readers stay. If you may want it later, keeping the endpoint is cheap and it could be rebuilt in a day. Detail: docs/research/holistic-review-decisions.md.
